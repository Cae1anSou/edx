# RFC-003: 直接替换（Big-Bang Cutover）执行方案

- Status: Draft
- Date: 2026-02-27
- Owner: Backend Refactor Team

## 1. 决策

系统尚未上线，迁移策略调整为直接替换：上线时仅启用 Spring 后端，不保留 Django 生产承载路径。

## 2. 执行边界

### 上线前必须完成
1. 核心域 API 在 Spring 完成可用实现：用户、选课、学习进度、评分、证书。
2. 数据库 schema 与初始化数据方案在 Flyway 固化。
3. 关键接口契约测试通过（前端联调覆盖主流程）。
4. 运维脚本改为仅部署 Spring 服务。

### 上线前可暂缓
1. 历史 Django 管理后台的功能完全等价迁移。
2. Celery 全部任务迁移（保留离线脚本替代也可）。

## 3. 当前落地状态

已在 Spring 侧提供以下起点能力：
- 用户域：注册/查询
- 选课域：选课/退课/查询
- 通知偏好域：查询/更新 + 幂等键 + 变更事件

## 4. 风险与控制

1. 风险：一次性切换可能遗漏 API  
   控制：建立 API 清单对照，逐条打钩，不满足不发布。
2. 风险：前端契约字段不一致  
   控制：OpenAPI 生成 + 自动化契约测试。
3. 风险：环境配置差异  
   控制：仅保留一套 Spring 部署配置并在预发全量演练。

## 5. 里程碑

1. M1（本周）：Spring 承载用户/选课/通知基础链路。
2. M2（下周）：学习进度与成绩最小闭环。
3. M3：证书与后台运营基础能力。
4. M4：删除 Django 部署链路，切换为 Spring-only。
