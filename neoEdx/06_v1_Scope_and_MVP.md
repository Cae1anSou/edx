# NeoEdx v1 范围冻结与 MVP 定义（Scope & MVP）

> 目标：从逆向文档中“冻结”一个可交付的 v1 闭环（MVP），作为第二步（新实现设计）的唯一输入范围。  
> 约束：以行为与边界为准，不绑定实现技术。行为来源见 `neoEdx/05_Behavior_Coverage_Matrix.md`。

## 1. v1 目标（Goals）

- 提供一个可用的在线学习闭环：发现课程 → 报名（含付费）→ 学习 → 提交与评分 → 成绩展示 → 证书生成与验证。
- 支持课程创作与发布闭环：创建课程 → 编辑结构/内容 → 发布并进入目录可发现。
- 支持最小教学运营：教师能看进度看板并导出成绩/提交报表。
- 支持最小学习社区与沟通：课程讨论发帖/回复，关键事件触发通知，用户可管理通知偏好。

## 2. v1 非目标（Non-goals）

以下明确不进入 v1（即使现有系统具备），除非后续范围变更：

- 监考/考试诚信、违规处置与申诉编排（Integrity/Support 深度能力）
- Cohort 分组与按分组切分内容/讨论（Cohorts）
- 退款全流程与“已发证后退款”治理规则
- 团队协作（Teams）
- 课程重跑（Course rerun）
- 内容库复用、复杂版本管理
- 第三方登录（OAuth/SAML 等）
- 邮件通知渠道（仅站内通知）
- 学分认证、项目/路径（Credit/Programs）
- 高级运营（专题页复杂运营、个性化推荐、复杂增长实验）
- 高级分析与预测、全量审计视图（仅保留最小可追溯语义）

## 3. 用户角色与权限（v1）

- 学习者：浏览/搜索课程、报名、学习、提交、查看成绩/证书、参与讨论、管理通知偏好
- 课程创作者：创建课程、编辑内容结构、发布课程
- 教学团队：批改与成绩处置（至少支持手动评分）、查看进度/导出报表
- 运营/管理员：基础站点配置（身份/支付/消息通道等集成项的配置入口）、课程可见性与目录发布（最小能力）

> v1 权限模型只需要支持“课程内角色与范围”的最小实现语义；细粒度 ABAC、组织/租户等能力推迟。

## 4. v1 领域边界（Owner Domains）

v1 必须明确边界归属（实现可单体/多模块/多服务，但边界不变），详见 `neoEdx/02_Domain_Map.md`：

- Identity、Catalog、Course、Content、Enrollment、Commerce、Grades、Certificates、Discussion、Notifications、Reporting、Platform

## 5. v1 MVP 范围（按端到端旅程冻结）

### 5.1 发现与课程决策（Catalog）

- J1-01：搜索与筛选课程；结果仅包含对该学习者可见的条目
- J1-02：查看课程详情与权益说明（价格/证书权益/关键日期）

### 5.2 账号与身份（Identity）

- J2-01：注册与邮箱验证
- J2-02：本地凭证登录（第三方登录 v2）
- J2-03：密码重置

### 5.3 报名与付费（Enrollment + Commerce）

- J3-01：免费报名（旁听）并获得访问资格
- J3-02：付费购买并获得相应注册模式权益（含“影响证书资格”的语义）

### 5.4 学习与进度（Content）

- J4-01：按课程结构学习与导航；记录学习进度
  - 进度口径（v1）：记录访问 + 完成度百分比（完成阈值由课程配置定义）

### 5.5 提交与评分（Grades）

- J5-01：提交测验/作业答案并记录提交
- J5-02：客观题自动评分并展示结果（v1 至少支持一种：例如选择题）
- J5-03：主观题手动评分并留痕（v1 至少支持一种：例如简答题；需记录操作者、时间、原因/反馈）

### 5.6 证书（Certificates）

- J6-01：满足通过条件后生成证书（可异步），证书可下载
- J6-02：第三方证书验证（基于唯一标识）

### 5.7 讨论与通知（Discussion + Notifications）

- J7-01：课程讨论发帖与回复（按“已报名可发帖”的最小规则）
- J8-01：关键事件触发通知（成绩、证书、讨论回复等）
- J8-02：用户配置通知偏好，通知可标记已读

### 5.8 创作与发布（Course + Content + Catalog）

- J9-01：创建课程与课程配置（最小：关键日期、能力开关、课程团队与权限）
- J9-02：编辑课程结构与内容块，并发布内容版本
- J9-03：课程发布后进入目录并可被发现/报名（“可见”与“可报名”的语义分离）

### 5.9 教学看板与导出（Reporting）

- J13-01：教师进度看板（最小：人数、完成率/进度分布、最近活跃等基础指标）
- J13-02：导出成绩/提交报表（生成导出任务与可追踪状态）

## 6. v1 的“最小验收口径”（Definition of Done）

### 6.1 闭环验收（必须能走通）

- 学习者能在目录中发现一门课程 → 报名 → 学习至少一个单元 → 提交一次作业/测验 → 获得分数 → 达到通过条件（v1 默认 70%）→ 获得证书 → 第三方可验证该证书。

### 6.2 边界验收（必须不越界）

- Catalog 不直接修改报名/成绩/证书状态；仅维护目录视图与可见性规则。
- Reporting 不回写成绩真值；成绩变更必须回到 Grades 并留痕。
- Commerce 的支付结果必须可追溯到 Enrollment 的“权益变化”，并能解释“为什么可拿证/不可拿证”。

### 6.3 可追溯验收（最小治理要求）

- 成绩手动评分/覆盖必须记录：操作者、时间、原因/反馈（语义即可）。
- 证书生成/撤销（v1 只做生成）必须可追溯到资格判定输入（成绩/报名模式）。

## 7. v1 关键范围切分（第二步设计的强制输出）

第二步（新实现设计）必须交付以下“边界契约”，否则 v1 容易失控：

- “课程可见（Catalog）” vs “可报名（Enrollment）” vs “可学习（Content）” 的判定顺序与冲突处理。
- “证书资格”的输入集合：报名模式/权益（Enrollment/Commerce） + 成绩（Grades） + 课程策略引用（Course）。
- “进度”归属与口径：Content 记录事实进度；Reporting 聚合展示；Grades 的完成/通过口径明确。
- 事件清单（最小）：CoursePublished、EnrollmentChanged、SubmissionReceived、GradeChanged、CertificateStateChanged、ThreadCreated/CommentCreated、NotificationSent、ExportJobCreated/Completed。

## 8. 里程碑建议（不绑定实现方式）

- M0：范围冻结与术语对齐（本文件 + 术语表若需要）
- M1：学习闭环 Alpha（免费报名 + 学习 + 提交/评分 + 成绩展示）
- M2：商业闭环 Beta（付费购买 → 权益生效 → 影响证书资格）
- M3：证书与验证 GA（证书生成/下载/验证 + 关键通知）
- M4：教学运营 GA（进度看板 + 成绩/提交导出）

## 9. 风险与需要提前确认的问题

- 题型范围：v1 是否只支持一种评估类型（客观/主观各至少一种）？
- 证书规则：通过条件的最小定义（百分比/必做项/时间窗口）需要谁来拍板？
- 支付与权益：是否存在多模式（audit/verified 等）的精确语义需求？退款是否完全推迟？
- 合规与隐私：v1 是否必须支持“账户删除/匿名化”的最低合规路径？
