# NeoEdx 架构概览

> 本文档用于“逆向阶段”的架构澄清：以行为与领域边界为核心，描述 NeoEdx 的逻辑架构（C4 Level 1–2），刻意避免绑定具体技术栈与部署形态。

---

## 一、系统上下文（C4-L1）

### 1.1 参与者（Actors）

- 学习者：发现课程、报名、学习、提交、查看成绩/证书、参与讨论
- 教师/助教：配置课程、发布公告、批改与成绩处置、教学报表
- 课程创作者：创作/组织内容、发布课程
- 运营/管理员：目录运营、站点配置、商业配置、治理与审计
- 客服/治理人员：支持工单、举报审核、合规请求处理
- 外部合作方：身份提供商、支付通道、学分提供商、（可选）监考服务

### 1.2 外部系统（External Systems）

- 身份提供商（SSO/OAuth/SAML/LTI 等）：登录与身份断言
- 支付通道：订单支付与退款
- 邮件/消息通道：邮件与通知投递
- 内容分发与文件存储：视频/证书/导出文件的分发与存储
- 学分提供商：学分申请/成绩单投递
- （可选）监考服务：监考会话与证据处理

## 二、逻辑容器（C4-L2）

### 2.1 客户端应用（按行为分区）

- 学习端（Learner Experience）：目录发现、学习、提交、讨论、个人学习记录
- 创作端（Authoring/Studio）：课程结构与内容创作、发布、课程团队与权限
- 教学端（Teaching Console）：进度与成绩处置、报表导出、群发通知
- 运营与管理端（Admin Console）：站点配置、目录运营、商业配置、审计与治理
- 支持与治理端（Support Console）：工单处理、举报审核、合规请求执行

### 2.2 后端能力（按领域边界组织）

后端以领域（Bounded Context）组织核心能力；其实现可以是“模块化单体”或“可拆分的服务集合”，但边界与职责保持一致：

- Identity（用户域）
- Course（课程域）
- Content（内容域）
- Enrollment（注册域）
- Cohorts（分组域）
- Grades（成绩域）
- Certificates（证书域）
- Discussion（讨论域）
- Notifications（通知域）
- Teams（团队域）
- Commerce（商业域）
- Catalog（目录发现域）
- Reporting（报表分析域）
- Integrity（诚信监考域）
- Support（支持治理域）
- Programs（项目路径域）
- Credit（学分域）
- Platform（平台域：配置/主题/国际化/审计策略等横切能力的“归口”）

## 三、领域到行为映射（边界校验）

| 领域 | 主要负责的系统行为（示例） |
|------|----------------------------|
| Catalog | 课程/项目可见性、搜索与筛选、类目专题页、营销信息发布 |
| Course | 课程生命周期、课程配置与能力开关、课程团队与权限 |
| Content | 内容块与结构、版本/发布、内容库复用 |
| Enrollment | 报名/退课/升级模式、席位与权益、资格校验 |
| Cohorts | cohort 创建/分配/查询；为内容/讨论/通知提供分组切分输入 |
| Grades | 提交与评分、成绩计算、覆盖与申诉、成绩政策与例外 |
| Certificates | 证书生成/撤销/验证/补发 |
| Discussion | 发帖/回复/审核、投票、按课程/分组的讨论体验 |
| Notifications | 通知偏好、站内通知、课程群发、通知投递与可追溯 |
| Commerce | 订单、支付、优惠、退款（输出“权益变化”给注册域） |
| Reporting | 教学看板、导出任务、审计视图（不拥有成绩/注册真值） |
| Integrity | 监考规则、会话、证据与违规处置决策（影响由成绩/支持等域执行） |
| Support | 工单、举报治理、合规请求与留痕（通过各域公开能力执行动作） |
| Programs | 项目/路径定义、项目报名与项目级进度 |
| Credit | 学分资格、申请、成绩单投递 |
| Platform | 站点级配置、主题/语言、审计策略与全局开关 |

## 四、跨领域协作（通信语义）

### 4.1 同步交互（查询与小范围命令）

- 查询：一个领域读取另一个领域的“公开视图”（例如：成绩域查询注册域判断是否已注册）
- 命令：需要即时反馈、且边界清晰的动作（例如：注册域提交“报名”命令并返回结果）

### 4.2 异步交互（领域事件）

- 用于跨领域的状态联动与耗时操作（例如：成绩变更触发证书重新评估与通知）
- 事件是事实描述而非过程调用；消费方自行决定如何反应（并保证幂等）

### 4.3 关键事件流（示例）

| 事件 | 产生方 | 典型消费者 | 说明 |
|------|--------|------------|------|
| CoursePublished | 课程域 | 目录发现域、通知域 | 课程进入目录、对学员可见（按规则） |
| EnrollmentChanged | 注册域 | 成绩域、通知域、报表分析域 | 学员资格变化、报表刷新 |
| CohortChanged | 分组域 | 内容域、讨论域、报表分析域 | 分组切分在各域边界内生效 |
| GradeChanged | 成绩域 | 证书域、通知域、报表分析域 | 证书资格与通知联动 |
| CertificateStateChanged | 证书域 | 通知域 | 证书生成/撤销通知 |
| IntegrityViolationAdjudicated | 诚信监考域 | 支持治理域、成绩域（按策略） | 处置与申诉（若启用） |
| SupportTicketUpdated | 支持治理域 | 通知域 | 工单状态通知 |

## 五、横切关注点（不属于单一业务域）

- 认证与授权：全局身份、课程内角色、操作权限与审计留痕
- 审计与可追溯：关键动作（成绩覆盖、证书撤销、退款、封禁等）必须可追溯
- 合规与隐私：数据导出/删除/匿名化请求与执行记录
- 可观测性：日志、指标、追踪的统一语义与责任归属
- 配置与特性开关：站点级/课程级能力开关与变更影响面评估

## 六、待第二步决策（刻意不在逆向阶段绑定）

- 部署形态：模块化单体 vs 可拆分服务；拆分顺序与演进路径
- 数据存储策略：各域数据边界落地方式与一致性策略
- 通信协议与事件基础设施：API 风格、事件总线与任务队列选型
- 前端形态：单体前端、模块化前端或多应用组合
